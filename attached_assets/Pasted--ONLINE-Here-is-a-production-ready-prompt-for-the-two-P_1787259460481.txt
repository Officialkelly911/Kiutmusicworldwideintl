The completion review identified two non-blocking metadata consistency issues that must be resolved before Phase 11D is considered fully production-ready.

1. Fix the build-time HTML metadata fallback

The current Vite build process generates:

dist/public/index.html

using the 404 document context rather than the homepage context.

The Express production server correctly resolves route-specific metadata at request time, but the generated static build artifact itself can contain the 404/noindex JSON-LD context.

This must be corrected.

Required behavior

Update the Vite/build-time HTML transformation so that:

* When the build process has no request URL available, it defaults to /.
* The homepage / receives the homepage metadata and homepage structured-data graph.
* Development requests continue using their actual request URL.
* Production Express requests continue using their actual request URL.
* Route-specific initial HTML metadata remains intact.
* The existing Phase 11B SEO metadata implementation must not regress.
* Phase 11C server-level 404 behavior must not regress.

The fallback hierarchy should effectively be:

Actual request URL
        ↓
Use that route
        ↓
If no request URL exists during static build
        ↓
Fall back to "/"

Do not hard-code homepage metadata into every route.

Do not remove the existing request-aware transformation.

2. Resolve the unresolved inAlbum references

The current structured-data graph contains standalone music recordings that reference:

#album-singles

through inAlbum.

However, the corresponding MusicAlbum entity may be excluded from the emitted graph because its aggregate release date is not sufficiently complete.

This creates a JSON-LD reference to an entity that may not actually exist in the same graph.

Required behavior

Review the existing album and recording data and implement a fact-based solution.

Use this decision logic:

If the referenced MusicAlbum has sufficient verified existing data
    → emit the MusicAlbum entity
    → retain the MusicRecording.inAlbum reference
If the MusicAlbum is not emitted
    → omit the inAlbum property from that MusicRecording

Do not invent:

* release dates
* album dates
* track counts
* album names
* durations
* platform information
* other unsupported metadata

The structured-data graph must never contain an unresolved internal entity reference.
