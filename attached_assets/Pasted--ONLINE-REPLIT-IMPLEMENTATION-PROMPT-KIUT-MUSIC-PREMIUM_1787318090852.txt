REPLIT IMPLEMENTATION PROMPT

KIUT MUSIC — PREMIUM DIGITAL ARTIST EXPERIENCE REFINEMENT

ROLE

Act as a senior product designer, creative director, frontend engineer, motion designer, and UX/performance engineer working on the existing KIUT Music production website.

The objective is not to redesign the website from scratch.

The objective is to refine the existing experience so KIUT feels more like a cinematic digital artist universe rather than a conventional artist catalogue, while preserving the established KIUT identity, SEO architecture, performance work, responsive behavior, and existing functionality.

Use the existing production implementation and the supplied website screen recording as visual reference for the current state.

⸻

1. NON-NEGOTIABLE CONSTRAINTS

Before modifying anything:

1. Inspect the existing implementation thoroughly.
2. Do not rebuild the application from scratch.
3. Do not replace the existing design system unnecessarily.
4. Do not alter the approved KIUT logo, brand colors, typography system, or core visual identity unless a specific refinement requires it.
5. Do not modify:
    * robots.txt
    * sitemap.xml
    * canonical architecture
    * server-rendered SEO metadata
    * JSON-LD architecture
    * 404 behavior
    * route structure
    * analytics configuration
6. Preserve all existing public routes.
7. Preserve existing music, video, tour, newsletter, contact, legal, and merchandise functionality.
8. Do not invent artist information, release dates, credits, statistics, tour dates, streaming numbers, or other facts.
9. Do not introduce unnecessary dependencies.
10. Do not introduce heavy animation libraries when CSS/native browser APIs can accomplish the same result.
11. Do not sacrifice mobile performance for visual effects.
12. Respect prefers-reduced-motion.
13. Do not add autoplaying media that significantly increases the initial page payload.
14. Do not introduce scroll-jacking.
15. Do not create visual clutter.
16. Do not make every section animated simply because animation exists.
17. Existing content should be reused wherever possible.

Core principle

Premium must never mean heavier.

The website should feel more cinematic while becoming no slower to load.

⸻

3. IMPLEMENTATION ORDER

Implement the refinement in controlled stages.

STAGE A — HOMEPAGE HERO EXPERIENCE

Refine the homepage opening so it feels like an intentional cinematic introduction.

Use the existing hero assets and approved release content.

Desired sequence:

1. KIUT monogram/brand mark establishes the frame.
2. Background visual/video resolves subtly.
3. Release label appears.
4. Main release title enters.
5. Supporting information appears.
6. CTA becomes visible.

Animation should be approximately 1–1.5 seconds maximum and should not delay interaction.

Use opacity, transform, blur/reveal, and subtle scale transitions rather than complicated animation systems.

Important

Do not block the page from rendering while the animation runs.

The content must remain accessible if animation is disabled.

28. IMPLEMENTATION DISCIPLINE

Do not implement all visual ideas blindly.

First inspect the existing components and identify which requested improvements can be achieved through small targeted refinements.

For every proposed change:

1. Identify the existing component.
2. Identify existing data/assets.
3. Reuse existing functionality.
4. Make the smallest clean implementation.
5. Test it.
6. Check mobile.
7. Check performance.
8. Check for regressions.

If an asset is missing, do not fabricate it.

If a requested feature conflicts with the existing architecture, preserve the architecture and implement the closest lightweight equivalent.
