KIUT MUSIC — ROMANTIC LOVE STREAMING LANDING PAGE INTEGRATION

OBJECTIVE

Integrate the official Romantic Love streaming-platform landing page throughout the KIUT Music website wherever users are presented with an opportunity to listen to, discover, or access the Romantic Love release.

Official Romantic Love Streaming URL

https://bit.ly/m/Romanticlove

Treat this as the canonical external destination for the Romantic Love release.

⸻

1. CENTRALIZE THE URL

First inspect the existing Romantic Love release data and determine where the track/release metadata is stored.

Add the streaming landing page URL to the centralized Romantic Love release data.

For example, if the existing structure supports a field such as:

streamingUrl

or:

listenUrl

or:

releaseUrl

use the existing field.

Do NOT create a new field if an appropriate existing field already exists.

The canonical value must be:

https://bit.ly/m/Romanticlove

Do not modify the URL.

Do not replace it with individual Spotify, Apple Music, YouTube Music, or other platform URLs.

The Bitly landing page is intended to route users to the appropriate streaming platforms.

⸻

2. HOMEPAGE HERO — ROMANTIC LOVE

The homepage Hero currently has Romantic Love — Recent Release as the first slide.

Ensure the primary CTA on this slide points to:

https://bit.ly/m/Romanticlove

The CTA should use the existing premium reusable CTA component.

For example:

LISTEN NOW

→ https://bit.ly/m/Romanticlove

Do not create a new CTA design.

Do not modify the existing CTA animation.

⸻

3. MUSIC PAGE — RECENT RELEASE

On the Music page, Romantic Love is already implemented as the recently released single.

Ensure the primary action associated with the release points to:

https://bit.ly/m/Romanticlove

This should apply wherever the Music page presents an action such as:

* Listen Now
* Stream Now
* Listen on Streaming Platforms
* View Release
* Explore Release

Use the existing CTA/button component and styling.

Do not create duplicate buttons simply to accommodate the URL.

⸻

4. ROMANTIC LOVE AUDIO PLAYER

The website’s internal audio player should remain separate from the streaming landing page.

If the Music page contains an internal player for the uploaded Romantic Love audio file:

* Keep the internal audio player.
* Keep Play/Pause functionality.
* Do not replace the audio file with the Bitly URL.
* Do not attempt to load the Bitly URL as an audio source.

The architecture should be:

ROMANTIC LOVE
│
├── Internal Audio Player
│   └── Uploaded Romantic Love audio file
│
└── Listen / Streaming CTA
    └── https://bit.ly/m/Romanticlove

This allows visitors to preview/listen through the website while also giving them a direct route to the official streaming-platform landing page.

⸻

7. FUTURE-PROOF THE IMPLEMENTATION

The streaming URL must come from the centralized Romantic Love release data.

Avoid implementations such as:

onClick={() => window.open("https://bit.ly/m/Romanticlove")}

repeated across multiple components.

Instead, use the existing release data:

Romantic Love
    ↓
centralized release data
    ↓
streamingUrl
    ↓
Hero CTA
Music Page CTA
Release Card
Featured Release

This ensures there is one source of truth.

Because this is an external streaming-platform landing page, follow the website’s existing external-link convention.

If the existing website opens external destinations in a new tab, preserve that behavior.

If the existing architecture uses:

target="_blank"
rel="noopener noreferrer"

follow the established pattern.

Do not introduce a different external-link behavior specifically for Romantic Love.

⸻

9. DO NOT ALTER THE BITLY URL

Use the URL exactly as provided:

https://bit.ly/m/Romanticlove

Do not:

* Add tracking parameters
* Replace it with another URL
* Expand the Bitly link
* Create another shortened link
* Modify capitalization
* Add unnecessary query parameters

unless an existing analytics architecture automatically handles tracking without changing the canonical destination.
