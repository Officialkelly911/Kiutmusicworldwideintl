PHASE 11B — SERVER-DELIVERED PAGE SEO METADATA
HIGH PRIORITY SEO IMPLEMENTATION

Use the completed Phase 11A SEO audit as the authoritative specification for this phase.

The objective is to eliminate the current production issue where non-homepage routes initially return the homepage's SEO metadata in the raw HTML and only receive their correct metadata after client-side JavaScript executes.

CURRENT ISSUE CONFIRMED BY AUDIT

Direct production requests to:

https://kiutmusic.com/music
https://kiutmusic.com/videos
https://kiutmusic.com/about
https://kiutmusic.com/tour
https://kiutmusic.com/newsletter
https://kiutmusic.com/contact
https://kiutmusic.com/legal

currently return the same initial SPA HTML shell containing:

- Homepage title
- Homepage meta description
- Homepage canonical
- Homepage Open Graph metadata
- Homepage Twitter metadata
- Global MusicGroup JSON-LD

The correct route-specific metadata is then applied only after the React application mounts and the existing useSEO() logic executes.

This must be corrected.

==================================================
1. PRIMARY OBJECTIVE
==================================================

Ensure every public route has correct SEO metadata available in the INITIAL production HTML response.

Google, social crawlers, link preview systems, and other non-JavaScript consumers must receive the correct metadata without depending on client-side JavaScript execution.

The following must be route-specific in the initial HTML:

- <title>
- meta description
- canonical URL
- robots directive
- Open Graph title
- Open Graph description
- Open Graph URL
- Open Graph image
- Open Graph type
- Twitter card
- Twitter title
- Twitter description
- Twitter image

Do not remove the existing client-side SEO system until the server-delivered solution is confirmed working.

The client-side metadata system may remain as a hydration/runtime fallback if necessary.

==================================================
2. PUBLIC ROUTES
==================================================

Implement initial HTML metadata for:

/
 /music
 /videos
 /about
 /tour
 /newsletter
 /contact
 /legal

Do not create SEO metadata for private, administrative, development, API, or internal routes.

==================================================
3. PRESERVE EXISTING SEO CONTENT
==================================================

Use the existing route-specific SEO metadata already defined in the project as the source of truth.

Do NOT invent new marketing copy.

Do NOT unnecessarily rewrite:

- titles
- descriptions
- branding language
- page content

The goal is to change WHEN the metadata is delivered, not arbitrarily change WHAT the metadata says.

Preserve the existing approved KIUT Music brand voice.

==================================================
4. CANONICAL URL REQUIREMENTS
==================================================

Every public page must expose its correct canonical URL in the initial HTML.

Use:

https://kiutmusic.com/

Examples:

Homepage:
https://kiutmusic.com/

Music:
https://kiutmusic.com/music

Videos:
https://kiutmusic.com/videos

https://kiutmusic.com/about

Tour:
https://kiutmusic.com/tour

Newsletter:
https://kiutmusic.com/newsletter

Contact:
https://kiutmusic.com/contact

Legal:
https://kiutmusic.com/legal

Do NOT emit:

- Replit URLs
- localhost URLs
- development URLs
- www.kiutmusic.com URLs

unless explicitly required by the existing production configuration.

==================================================
5. QUERY STRING HANDLING
==================================================

Ensure tracking parameters do not become separate canonical URLs.

For example:

https://kiutmusic.com/music?utm_source=instagram

must still declare:

https://kiutmusic.com/music

as the canonical URL.

Do not remove legitimate query parameters from application functionality.

Only the canonical SEO signal needs to remain clean.

==================================================
6. OPEN GRAPH
==================================================

Ensure initial HTML contains:

og:title
og:description
og:url
og:image
og:type

Use absolute production URLs where appropriate.

For example:

https://kiutmusic.com/og-image.png

rather than relying unnecessarily on root-relative values.

Preserve the existing approved social image unless a page-specific image already exists.

Do NOT redesign or replace social graphics.

==================================================
7. TWITTER/X METADATA
==================================================

Ensure initial HTML contains:

twitter:card
twitter:title
twitter:description
twitter:image

Use the same approved metadata values currently defined by the application unless a route-specific value already exists.

Do not invent social account metadata.

==================================================
8. ROBOTS META
==================================================

Ensure public pages expose an appropriate robots directive in initial HTML.

Default public pages should remain indexable unless the existing project explicitly defines otherwise.

Do NOT introduce noindex directives.

Do NOT alter robots.txt.

==================================================
9. STRUCTURED DATA
==================================================

Do NOT implement the Phase 11D structured-data work yet.

Preserve the existing global MusicGroup JSON-LD.

Do not duplicate or remove existing structured data unnecessarily.

This phase is specifically about initial HTML metadata.

==================================================

The project currently uses:

- Wouter
- React

- lazy-loaded route components
